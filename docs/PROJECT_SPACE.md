# Project Spaces

A Project Space is the durable authority for one body of work. It combines approved live roots, immutable resource versions, retained ChatGPT/Gemini history, current working state, retrieval, snapshots, and outgoing provenance.

## Normal use

Add or link project material once, then edit files normally on disk. Watchers mark/index changes in the background, and the mandatory native-send barrier reconciles real bytes again before a guaranteed send. The user does not re-upload revised text/code/PDF material or tell the model which version changed.

Files, PDFs, images, and screenshots introduced through an associated native chat also become durable resources. A unique exact match to an approved-root current version is reconciled; an external/pathless input is archived privately without authorizing its parent directory or writing into the repository. The Resource Library shows whether the origin was a project folder, pasted into a provider, attached in a provider, or generated by a provider. **Save copy to project folder** is optional explicit export.

New managed spaces live under `%USERPROFILE%\Documents\AI Workspace\Projects`. Repositories and explicit linked folders may remain in their canonical location. Add a source from the Harness UI's native folder picker; each root has independent required/indexed/provider-allowed policy. Local-only roots can participate in local state but cannot enter ChatGPT/Gemini context or attachments.

**Remove Project Space** disables Harness tracking/watchers and removes the space from the active selector only after confirmation. It does not delete the live project folder and does not erase retained archive/history. The last active Project Space cannot be removed until another exists.

## Continuity

All capturable original messages remain retained. Fresh chats receive compact working state, recent continuity, and query-specific evidence rather than every historical byte. Retrieval spans user messages, ChatGPT, Gemini, decisions, tasks, current files, repository content, and PDFs. User reasoning and explicit decisions receive stronger weight than old assistant answers. Complete captures retain provider parent-message IDs and visible/alternate message-path state, so edited/regenerated branches are not flattened into one false timeline.

Uncaptured activity is never invented. Coverage stays `PARTIAL` or `UNKNOWN` until evidence/imports establish completeness. A chat with an observed attachment remains incomplete until the actual bytes, derived state, and search representation are durable.

## Integrity states

- **Project Current:** a specific managed-send snapshot verified every required source, current versions/index, repository observation, visible chat synchronization, matching generations, and active security policy.
- **Verifying Project:** reconciliation is in progress.
- **Context Stale:** a change was observed or no verified snapshot exists; the next managed send verifies again.
- **Context Blocked:** a required check failed. The native message remains in the composer and is not replayed.

Unchanged roots use their persisted manifest fast path (zero content hashes); changed candidates alone are hashed and processed, with a second inventory rejecting races. **Full integrity verification** is the explicit all-byte audit. Always-consider and context-critical resource policies provide deterministic retrieval/readiness controls, while superseded knowledge is retained for historical queries but excluded from ordinary answers.

`Harness ready` only means the local service and paired companion are connected. `safe_to_delete` only means every preservation stage for a provider chat is complete. Neither is a synonym for Project Current.

## Native interfaces

Discussion remains on chatgpt.com and gemini.google.com. The companion can associate directly opened chats with the explicitly active Project Space, reconnect known provider IDs, and reject a cross-workspace mismatch. The dashboard is the normal control plane for sources, resources/versions, processing, instructions, personalization, security, agents, backup, diagnostics, and updates. It is not a chat frontend or IDE and does not grant browser providers filesystem, shell, or Git capabilities.

Codex/Antigravity may be opened only on a registered repository root. Harness injects an expiring read-only context token and helper into that launched process. The token is workspace/root/capability scoped, is stored hashed, has no write endpoint, and never grants another repository or private database access.
